## What the build agent got wrong and how to avoid it

- **It claimed a guard it had not tested against the rule.** The PR says "any other `*Slider` class fails", but the regex only caught names ending in `Slider`. *Avoid it:* for every CI guard, run the script against a short table of bad and good inputs (a throwaway temp tree is enough) and paste the table into the PR. Test the approval's exact wording ("allow only `BioSliderView`"), not a paraphrase.
- **It probed the wrong number.** It assumed `PreviewView` puts its scale in `TextureView.setTransform()`. CameraX uses View `scaleX`/`scaleY`. A probe that reads the wrong field gives a clean-looking log over a stretched picture, which is worse than no probe. *Avoid it:* when a diagnostic depends on library internals, read the library (source or `javap -c` on the AAR in `~/.gradle/caches`) before writing the log line, and cite the method.
- **It fixed three of four call sites.** V2 named `paintStage`, `presentCamera`, and `onOutputSurface`; the agent stopped there and missed `live_output_drawer.kt`. *Avoid it:* after a "pick X everywhere" change, grep the whole module for the old pattern (`maxBy`, `maxByOrNull`) and list every hit in the PR as fixed or deliberately kept.
- **It skipped the ordering of writes across threads.** The overlay generation was bumped before the size it guards. *Avoid it:* when a counter guards data read on another thread, write the data first and the counter last, and say so in a comment.
- **It treated a debounce as a guarantee.** Debouncing collapses a burst, but the task must still check that its reason is still true when it runs. *Avoid it:* every delayed task re-checks its precondition at run time.
- **It wrote a phone test Royalty cannot run.** Step 2 of the progress note needs `adb logcat` on a PC; Royalty is phone-only. *Avoid it:* every phone test must be doable on the S25 and Phone 2 alone. If a number is needed from the device, build a way to get it on the phone (proposal below) or route it to Phone 2.
- **It bundled the probe with the fix it was meant to inform.** V2 row 0.5 says ship the probe and get one device log before 1.1 is designed in detail. This PR ships both together. That is acceptable only if the merge waits for the device log. *Avoid it:* when the roadmap orders "measure, then fix", either split the PRs or state in the PR that the merge is gated on the measurement.
- **It reused roadmap vocabulary for something else** ("Seam Weld" for the geometry helper) and gave a slightly wrong emoji count (69/10 vs 68/9). *Avoid it:* keep roadmap names for the roadmap's meaning; paste counts straight from the script output.

## Getting the RenderProbe lines without a PC (recommendation only, not built)

Royalty has no PC, so `adb logcat -s OffgridProbe` is not available. Recommended, for debuggable builds only:

1. **In-memory ring plus two small app-private files.** `RenderProbe` keeps its logcat sink and also feeds a ring of the last ~200 lines. On each bind it writes the ring for that bind to `filesDir/probe/cold_start.txt` (first bind after process start) or `filesDir/probe/resume.txt` (later binds), overwriting the previous copy. That captures a cold start even though the panel is not open yet. App-private storage needs no permission. (These runtime files are app data, not repository files, so the no-deletion rule is not involved.)
2. **`SYSTEM › Diagnostics › Render probe` (V2 §6 already places the probe here, behind the debug flag).** It shows the two captures as selectable text plus two actions: **Copy** (clipboard) and **Share** (`Intent.ACTION_SEND`, `text/plain`, `EXTRA_TEXT` through `Intent.createChooser`). She shares to Gmail, Messages, or Notes, or pastes into the chat. No `FileProvider`, no storage permission, no new manifest entry.
3. **Never on air.** The item exists only when `FLAG_DEBUGGABLE` is set. It is panel chrome, so Broadcast Lock (1.3) hides it, and it should refuse to open while recording or locked. Nothing is drawn on the stage. No toast.
4. **Later, Phone 2.** Phase 1.5's Geometry Attestation numbers (`previewAspect`, `slotAspect`, `stageAspect`, `clipAspect`) in the `State` packet make the same check readable on Phone 2 with no export at all.

Not recommended: on-device logcat reader apps (need `READ_LOGS`, granted only by `adb`), wireless-debugging tricks (need a second device and setup), or writing to shared storage (needs a permission).

Size: Fast tier. Files: `render_probe.kt` (ring sink and capture files), the Diagnostics folder builder in `terminal/EffectFolders.kt` or `PanelTree.kt`, a share action in `terminal/PanelActions.kt`. Tests: the ring keeps the last N lines, cold start versus resume files, and no item on a non-debuggable build.
