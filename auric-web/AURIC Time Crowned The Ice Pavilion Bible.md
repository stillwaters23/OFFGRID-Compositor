### Palette and timing invariants

All operational surfaces, numerals, accents, alert colors, chrome, and reel glow inherit semantic palette tokens. Selecting Pavilion, Pit, or Shadow must not overwrite the user's palette. The locked logo may stay blue. Contrast protection chooses readable foregrounds; light/ivory, red, gold, dark, and blue palettes all remain supported.

Accent and danger buttons use explicit readable foreground tokens, including alpha compositing against the base surface. The reel stays interactive DOM/CSS with touch, wheel, and keyboard control. Its readout participates in layout flow to avoid overlapping the primary action; digit sizing leaves room for aperture pointers. Reduced-motion preferences override decorative animation rules below.

Timer deadlines and running stopwatch anchors use timestamps rather than counting interval callbacks. Catch up on focus and visibility changes; one timer completion creates one session. Held timers retain their exact remaining time. Dated alarms honor seconds, recover when overdue, and queue coincident alerts. A service worker displays permitted notifications; it does not provide a native scheduler or guarantee an alarm when the browser is suspended or closed.

State remains local under `auric-crowned-v21`. Identical persisted snapshots do not repeatedly rewrite storage. Corrupt JSON or an unsupported saved-state envelope is copied to a timestamped recovery key before defaults may be saved. If that copy fails, protect the original and run without overwriting it. A PIN is a local privacy gate, not encrypted storage; changing the PIN invalidates the previous session marker.

The floating chip stays inside AURIC. Native overlays, system alarm scheduling, and paid billing remain separate future work. Crown is an explicitly labeled preview and does not charge a user.

## 7. Vault 03 — The Table · 77 families

`src/lib/faces.ts` contains the catalog, stable IDs, explicit supported weights, and sensible serif/sans/monospace fallbacks. Google Fonts metadata supports every current family and selected weight. The obsolete family name “Big Shoulders Display” becomes “Big Shoulders” while its saved `big-shoulders` ID remains compatible. Existing `mono`, `serif`, and `neon` aliases still resolve.

Each request uses the family's actual available weight. Single-weight display faces request 400; DM Mono requests 500; families with a supported bold face generally request 700. Do not request 500/600/700 indiscriminately.

The loader deduplicates active requests and tracks idle/loading/loaded/error. A successful stylesheet is insufficient: `document.fonts.load` must resolve to loaded font faces before marking success. Failure or timeout removes the failed stylesheet and permits retry. `src/lib/use-face.ts` subscribes to status and retries after an online event. Selection persists by stable ID; reloads must load the actual face again.

Numbers Settings separates browsing, preview, and Apply. Only a successfully loaded preview can be applied. Loading failures remain visible, offer Retry, and show the system fallback honestly. `FontApplier` changes digit family and weight globally without synthetic bold. Labels keep legible UI fonts. Only selected/previewed families are requested; the application does not preload all 77 fonts.

Network/binary delivery checks and browser rendering checks are distinct. See the QA report for what was actually verified. Analog faces remain original and palette-aware.
